# Standalone modeling read service

`createReadService(adapter, sessionId)` accepts an optional `geomTypes()` adapter. Without it, model-based geometry reads still work, but `geometry.listTypes()` rejects with `ENGINE_ERROR`. With it, the service calls the method with the adapter as receiver and no arguments; the adapter must implement any engine-side guarding it needs. The service validates and copies the returned string array. Ordinary adapter failures and invalid responses become `ENGINE_ERROR`; an adapter `ModelingError` with code `STALE_MODEL` is reported as `STALE_MODEL`, and closing the service takes precedence as `SESSION_CLOSED`.

The standalone service's `capabilities()` is a static description of its implemented feature categories, not a probe of adapter methods or engine availability. In particular, `geometry.read` remains `supported` even when `geomTypes` is absent or fails, so it does not guarantee that every geometry read will succeed. This is distinct from the browser facade, which supplies a scoped, guarded type adapter for its `geometry.listTypes` operation; its capabilities and engine declarations are described in [browserReadApi.md](browserReadApi.md).
