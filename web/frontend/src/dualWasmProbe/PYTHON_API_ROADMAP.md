# OpenVSP Python API: browser compatibility analysis and execution roadmap

This is an engineering analysis of the current checkout, not a claim that all APIs are browser-accessible. It combines source inspection with the existing fixed Chromium diagnostic documented in [PYTHON_PACKAGE_SAMPLING.md](PYTHON_PACKAGE_SAMPLING.md). The companion generated [native API inventory](NATIVE_API_INVENTORY.md) lists declarations and syntactically detected uses, with explicit limitations. The previous [package audit](PYTHON_PACKAGE_AUDIT.md) inventories Python modules; it does not measure compatibility percentages.

## Baseline and scope

- `src/geom_api/VSP_Geom_API.h` contains 1,028 textually detected `extern` function declarations, 1,017 names, 9 names with multiple declarations, and 46 Doxygen group definitions. These are not counts of SWIG exports or usable browser APIs. Classes, methods, operators, enums, other headers, `%ignore`, preprocessor conditions, build options, generated package helpers and dynamic exports require separate coverage. Run the generator again when source changes rather than treating these numbers as permanent.
- The static package audit covers 43 non-test/example `.py` modules and 431 AST function/method definitions. Package definitions, direct call sites and header declarations have different denominators. Dynamic dispatch, aliases and transitive calls are incomplete in static analysis.
- The synchronous Python facade has a reviewed, narrow experimental subset. It now includes the original geometry diagnostics plus owner-scoped parameter-ID reads and a one-shot ResultsMgr fixture for typed-result parser validation; these additions are not full native API compatibility. It is only used by fixed diagnostics and is neither an interactive Python environment nor an installed `openvsp` package. A same-name entry does not mean full native behavior; [SYNC_API.md](SYNC_API.md) describes the current restricted signatures and [README.md](README.md) records divergences.
- The fixed read probe executed the unmodified original `get_wing_reference_quantities` from the original utility module under an alternate module name, using a restricted facade, a `SET_ALL=0` import shim, and pinned same-origin NumPy/six. A single wing returned `[45,18,2.5]` by ID and name, matching independent engine reads. No claim is made for arbitrary models, functions, native import layout, or runtime API coverage.
- The installed browser modeling read service is asynchronous and distinct from both the diagnostic sync facade and native Python. More engine/modeling operations exist than the sync facade exposes; legacy routes are not equivalent to guarded native Python methods.

## Native Python contract: migration constraints

1. `src/python_api/CMakeLists.txt` builds native SWIG Python bindings using Python libraries and NumPy; the native package imports compiled `vsp` or `vsp_g`, or a subprocess/socket facade. The desktop facade in `src/python_api/auto_facade.py` uses subprocess, sockets and pickle and cannot simply be transplanted into Pyodide.
2. `src/geom_api/vsp_common.i` defines vector specializations, nested vectors, enums, classes and name-sensitive `OUTPUT` typemaps. Some C++ output parameters become Python return values; C++ signatures alone are insufficient. `vec2d`, `vec3d`, `Matrix4d`, errors, operators, ownership, NumPy conversions and class methods are part of the contract too. Getters returning references must copy data before the engine job ends or state mutates.
3. Native errors often queue an `ErrorObj` and return a default instead of raising (`src/geom_api/APIErrorMgr.h`). The diagnostic instead raises `OpenVSPError`; preserve that distinction explicitly. Do not silently destroy unrelated shared error state or claim error parity without tests.
4. Known overload names include `Print`, `GetSubSurf`, `DeleteSubSurf`, `SetSubSurfName`, `GetSubSurfName`, `ComputeFeaMesh`, `SetParmVal`, `SetParmValUpdate`, and `GetParmVal`. Particularly important: the parm-ID and geom/name/group overloads differ; native deferred `SetParmVal` is not equivalent to `SetParmValUpdate`.
5. Enums and defaults are part of import-time compatibility: the current `SET_ALL` shim is deliberately local to the fixed test. Automatically synthesizing other values or enabling every header declaration would be unsafe.

## Transport and engine findings

- All operations on the page's OpenVSP model must execute on its owning engine pthread via its queue; no direct cross-thread C++ access is permitted. The separate P1 diagnostic instead creates a fresh fixed test model in an isolated WASM instance: it does not access the page model. The sync worker waits via `SharedArrayBuffer` and `Atomics.wait`, while page dispatch remains asynchronous.
- The diagnostic keeps a 64 KiB response cap; it now serializes oversized responses as a small structured `RESPONSE_TOO_LARGE` error with write-aware outcome metadata. The Python facade validates envelopes and maps malformed transport responses to `INVALID_RESPONSE`/`TRANSPORT`; it does not raise the cap. A timed-out dispatched write may still complete: never retry it automatically; preserve unknown outcome and poison/close the session as designed.
- Engine jobs drain the queue before pumping the GUI, so sustained small calls can degrade responsiveness. The wing reference helper currently performs a sequential metadata scan; reviewed single-job bounded bulk reads can reduce round trips but do not by themselves guarantee an atomic multi-call Python workflow.
- A model epoch detects replacement, not same-model edits, pointer lifetime, ABA, a stable snapshot, or reentrancy. Current guard preflight is explicitly incomplete and blocks some script/custom geometry contexts. Each write's preflight, mutation, update, readback, error handling and UI/undo effects need review on the owner thread.
- `GetAndResetUpdateCount` is destructive and shared with the engine's watcher; do not expose it as an ordinary read. `VSPExit`, `VSPCrash`, and a failing `VSPCheckSetup` can terminate or damage the engine and should be denied rather than bulk-generated. Analysis getters and even apparent reads can touch global state; review implementation, not only names.
- `DeleteGeom` currently awaits the guarded deletion then explicitly returns `null` in the sync handler. Do not infer its Python return from the engine's internal result object. Other differences remain: fixed clone mode, descendant effects and update.

## Proposed implementation batches and exit criteria

**Batch 0 — reproducibility and contract.** Keep this inventory regenerated and add SWIG-export comparison when a native `openvsp` build is available. Set explicit reviewed policy per overload: scope, arguments/defaults, return shape, data type, side effects, thread/guard, lifetime, errors, and tests. Correct the oversized error envelope; test malformed/oversized/late responses and unknown write outcomes. Define queue/payload budgets and GUI responsiveness. Inventory is not an allowlist.

**Batch 1 — bounded geometry and parameter reads.** Implemented first owner-scoped increment: `GetGeomParmIDs`, `GetParmVal` by ID, `GetIntParmVal`, `GetParmName`, and `GetParmType`. IDs are revalidated against current-model geometry/XSec ownership on every request; unrestricted global `ParmMgr` lookup, `FindContainer`, and arbitrary `FindParm` remain unsupported. Browser smoke covers the existing model path; native SWIG differential coverage remains pending.

**Batch 2 — typed results and value objects.** Implemented a diagnostic-only, opaque one-shot ResultsMgr lease with fixed namedtuple-safe fields (`int`, `string`, `double`, `double matrix`, `vec3d`), bounded typed getters, engine-thread deep-copy serialization, explicit cleanup, and 30-second TTL cleanup. The unchanged original `parse_results_object` runs against this fixture in the fixed read smoke. This validates the parser and transport path, not arbitrary live result IDs or full Results Manager compatibility. DegenGeom and real analysis results remain a separate later batch.

**Batch 3 — controlled DegenGeom / SurfacePatches diagnostic.** The current-model path
encodes the live model to memory (no file, no filename change), decodes it into a fresh
disposable instance, and compares an ID-free model fingerprint on both sides before
returning results. It supports top-level POD/FUSELAGE/WING/STACK/BLANK/PROP only and
fails closed for other geometry types. Phase 1 measurements showed no value, update
count, selection, filename or results change from encoding; link metadata caches are
invalidated. See the README for the measured scope. The initial P1 increment executes both real analyses on fresh, fixed default WING and PROP models in a separate disposable WASM instance per analysis. It does not serialize, read or analyze the current page model: this avoids unproven rollback of DegenGeom's temporary geometry, caches and global state. Fixed inputs disable file output and mode application. A bounded, validated snapshot is fed to the unchanged original result, DegenGeom and SurfacePatches parsers in Pyodide. Post-analysis caps do not bound peak native analysis memory or CPU; the worker and WASM memory have separate limits. This is a diagnostic subset, not a general `ExecAnalysis`, shared-model analysis, or SWIG-compatible package. Full native differential tests and arbitrary-model isolation remain future work; do not claim AVL/CHARM support.

For a future current-model analysis, neither existing `snapshot` nor an unqualified XML roundtrip is a proven read-only clone: `WriteVSPFile` resets export paths via `SetVSP3FileName`; `Vehicle::WriteXMLFile` avoids renaming but `ParmContainer::EncodeXml` rebuilds cached groups and increments a global change counter, and vehicle encoding traverses global managers. CustomGeom and advanced links can compile or initialize scripts on load; NGon data is not persisted, and external resources/ID remapping require separate handling. Copying only `VspSurf` is not an independent clone either: it contains a raw foil-surface pointer, and `DegenGeom` holds a parent-geometry pointer. Moreover, native `Vehicle::CreateDegenGeom` includes temporary mesh trimming/mass-slice work and blank-geometry results beyond per-surface conversion. Even an empty top-level geometry tree does not prove an equivalent empty analysis: mode application, persistent analysis inputs, hidden/stored geometry and temporary mesh operations must be considered. A safe implementation must fail closed on unsupported state, capture and validate a source revision and identity across the operation, audit serialization effects or implement a genuinely read-only representation, and test source/clone equivalence. The existing model epoch changes on replacement rather than every edit, so it alone is not a sufficient revision check. Parameter enumeration alone does not preserve wing driver groups or all topology.

**Batch 4 — audited modeling writes and cross sections.** Implement individual overloads with native semantic contracts rather than equating existing guarded setters with native setters. Test undo, deferred updates, bounds, active parameters, failure/partial effects, reentrancy, stale IDs and concurrency on disposable models. Keep diagnostics opt-in and distinguish UI selection from creation.

**Batch 5 — explicit files, solver and GUI capabilities.** Specify FS boundaries, user approval, size limits, persistence, path mapping and provenance; isolate long-running analyses and solver workers. Desktop subprocess and GUI interfaces need replacements or explicit unsupported outcomes, not silent emulation.

For every batch, record static presence, implemented status, browser tests and native differential results separately. Include defaults/keywords, malformed arguments, empty/large returns, ordering, errors, value class identity, timeout, model replacement, engine build configuration and same-origin isolation. A percentage based solely on API names or header declarations would be misleading.

## Known gaps in this analysis

This is static source analysis plus previously documented narrow browser tests; the present environment did not import a native `openvsp` module for SWIG export introspection or run full native/browser differential tests. The inventories cannot fully resolve aliases, conditional imports, callbacks or runtime-generated methods. The OpenVSP header includes methods not applicable to ordinary scripts and may differ from SWIG's final export set. No non-root deployment, full package import, arbitrary Python, generalized filesystem, all analyses, solver workflows or numerical parity is established here.
