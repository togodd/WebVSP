# GUI XML 保存观察协议 v1（设计草案，未实现、未接入生产）

## 1. 目的与边界

本文补充 [文件写回设计](FILE_WRITEBACK_DESIGN.md)，只规定观察 OpenVSP GUI 发起的 `.vsp3` XML 虚拟文件写入；不是磁盘保存协议，不改变当前实现，不授权接入生产。事件是可丢失的观察信息，不是写回触发器、持久日志、事务提交或保存成功 UI 的依据。现有 watcher 的 mtime/size 判稳无法证明内容完整；本协议也不修复它。将来要安全写回仍须实现该设计中的绑定世代、目标身份、不可变快照、单目标串行、权限与失败处理等全部前提。

代码现状供实现者核查：`MainVSPScreen::NewModel` 的保存、`ExitVSP` 的保存以及 `ActionCB` 中 Save、Save As、Save Set 调用 `Vehicle::WriteXMLFile`；前三个菜单分支有的忽略 bool，Exit 随后直接退出。`Vehicle::WriteXMLFile` 经 `EncodeXml`、`xmlSaveFormatFile` 后返回 bool；成功仅表示当前函数所见的序列化/虚拟 FS 调用成功，具体 libxml 关闭和错误传播需实测，不能擅自升级为持久化保证。WASM 文件位于模块的虚拟文件系统，路径不是磁盘身份。API `WriteVSPFile` 和其它导出不在 v1 覆盖范围内，即使调用相同函数也不可伪装成 GUI 保存。

目前镜像输出由 `WebMirror::TakeOutput` 在互斥锁内交换并清空 outbox，`engine.cpp` 的 `take()` 将其放入 `mirror` 数组；输入 `PostEvent` 也入队。这里**没有宣称现有镜像队列已有界**。下文 bounded queue 是本协议单独提出的有界观察通道，不复用无界 outbox 充当可靠队列，也不改变既有 diff、dialog、输入的优先级或语义。

## 2. 观察点与范围

在 GUI 各分支的实际 `WriteXMLFile(savefile, set)` 调用周围放置仅限 Web 构建、仅观测的包装点：在动作入口分配操作号，在实际 `savefile` 确定后、调用返回时记录该路径与 bool，捕获异常则记录失败并按原有行为传播。禁止以修改 `Vehicle::WriteXMLFile` 全局语义来误包含 API 调用。覆盖 `save`、`save_as`、`save_set`、`new_save`、`exit_save`，保留 set 值。未选择路径、取消选择集或选择器时没有开始写入；可生成 `cancelled` 终态但不得声称曾有虚拟写，且不能靠选择器答复或 `dialog_done` 推断写入。若 UI 分支未插桩或进程在上报前退出，接收者无法推断其结果。

分配操作号须在相应 GUI 动作入口完成，以便把选择器取消关联到操作；Save Set 选择集取消也是如此。仅在写入调用实际进入时发 `started`，记录写入时实际传入的路径（包含引擎追加扩展名后的结果），不是页面预先绑定路径。取消分支发 `finished/cancelled`，无 path 和 set 时字段省略；不建立磁盘绑定。嵌套模态对话框及取消与写入调用点必须逐分支验证，不能只包最内层写函数。

## 3. 消息合同（建议，版本 1）

传输为与旧 `mirror`、`out`、`proc` 并列的可选 `saveObservation` 字段，仅协商成功后输出；示例为逻辑 JSON，非当前实现：

```json
{"saveObservation":{"v":1,"session":"opaque-random-id","lossEpoch":"0","events":[
  {"seq":"1","opId":"1","phase":"started","kind":"save_as","path":"/home/web_user/a.vsp3","set":0},
  {"seq":"2","opId":"1","phase":"finished","kind":"save_as","path":"/home/web_user/a.vsp3","set":0,"result":"virtual_write_succeeded"}
]}}
```

* `session` 为每次引擎启动不可复用的随机标识；`seq`、`opId`、`lossEpoch` 使用无符号十进制字符串，避免 JS 安全整数截断。每 session 的事件 seq 单调递增，操作号唯一；禁止回绕，耗尽时禁用观察并报告不连续。顺序是生产者发布顺序，不是磁盘操作顺序。所有字段长度须计入配额，路径只用于虚拟路径诊断，JSON 必须正确转义；不包含 XML 字节、句柄或用户文件内容。
* `started` 只代表进入调用，不承诺会有可见终态；`finished` 的 `result` 为 `virtual_write_succeeded`、`virtual_write_failed`、`cancelled` 或 `unknown`。`virtual_write_succeeded` 仅对应可验证的调用成功返回；false、异常是 failed，但可能已截断或部分写入；异常细节只给固定枚举错误码，不回传敏感路径以外的异常文本。`unknown` 用于无法判定，并非失败或成功。正常情况下每个操作一个终态；溢出、退出、崩溃或进程中断时消费者可能看不到它。
* `cancelled` 指 GUI 在实际写调用之前明确取消；绝不把关闭页面、超时、队列丢失或写入失败转换为取消。取消后不得出现同 op 的 started；一个已经进入写调用的操作不能回溯宣称取消。
* 引擎线程分配操作和事件序号，在线程安全队列同步发布；不在锁内执行 GUI、FS、序列化或等待 JS。仅当 `started` 和 `finished` 为同一个 op 且没有发生丢失、重启时可关联；接收者按 `(session, opId)` 去重，缺起始或终态归为未知，不自行补成功。

## 4. 有界队列、溢出与恢复

队列仅保存观察事件，采用 FIFO；设可配置上限 **256 条、64 KiB 编码字节**，以及每事件 **4 KiB** 上限（均为提议值，包含 JSON 转义后的 UTF-8 字节和队列开销预算；实现需计入对象与临时缓冲的额外固定/峰值内存，且分别限额）。生产者不得为等待消费者阻塞 GUI；不合并、不覆盖、不同操作间不挤占 diff/dialog 的资源。每次传输也有明确字节和条数上限，长路径或无法编码而无法纳入时视为丢失，不截断成另一条合法路径。

* 每次欲发布事件先分配 seq，再检查大小与容量；超限则拒绝**新事件**，保留队列已有事件，并同步递增单调 `lossEpoch`，置 sticky `loss`。饱和期间每个被拒事件都会推进 lossEpoch；溢出计数饱和、seq/epoch 耗尽或内存分配失败须进入永久不可信状态，不能回绕或伪称无丢失。`lossEpoch` 和 sticky 状态在队列外预留固定空间，不能依赖插入一条额外溢出消息；即使队列满、事件为零也在协商后的每次轮询响应中报告。溢出不得改变底层保存结果或阻塞引擎。
* `take()` 的观察子队列和元数据在同一互斥临界区取得一致快照并移除所取事件；下次响应继续带当前 `lossEpoch`。这是至多一次的本地交付，不是 ACK：交换后 JSON 构造、跨线程传输、解析或页面崩溃仍可能丢消息。任何这种错误、轮询中断/重连、session 改变、seq 缺口或 epoch 改变都使相关观察区间及所有尚未终结的操作变为 unknown。丢失的首条或末条无法仅由 seq 缺口检测；前端必须定期检查元数据，且不能由静默推断完整性。
* sticky 状态在本 session 中不清除；消费者可记录最新 epoch 作为新的诊断起点，但历史空洞不可恢复，不能声称已重新获得完整历史或完整快照。恢复后新操作仅可用于诊断，不能把这次基线当成写回授权；如需可靠重同步、保留未确认事件或恢复快照，须另设计有界 ACK/快照协议。
* 页面在停轮询、后台冻结、引擎退出或无下一次响应时可能永远看不到 loss；接收者应将所有未决操作标 unknown，不依赖超时认定取消、失败或成功。不得因溢出触发猜测性重试、重新写或自动下载。队列限制不约束 XML 构造、虚拟 FS 或现有其他队列的内存。

## 5. 协商与旧前端兼容

协议默认关闭。新页面须显式发送包含版本 `1` 的独立能力请求；引擎返回明确接受及新的 session 后才开始记录并输出可选字段。请求及响应本身须使用将来经验证的线程安全通道，并规定一次请求的超时/失败只表示未协商，不表示引擎不支持或保存失败。先未协商的动作不追补；重复请求幂等，不重置正在使用的 session 或丢失计数；多个消费者目前不支持，禁止把 destructive `take()` 当广播。

旧前端连接新引擎：没有能力请求，行为、消息及保存路径不变；新前端连接旧引擎：无明确接受即停用观察、保留原行为，不能无限等待或将缺事件视为成功。新旧组合均不要求旧前端认识新事件。版本不支持/协商失败时关闭观察；不能自动开启新写回。须验证旧解析器对额外字段的行为，但默认关闭不依赖其忽略未知字段。将来启用时协调发布，任何兼容性不确定都保持关闭。

## 6. 失败、风险及非目标

1. 虚拟成功不表示磁盘已保存：磁盘 handle 授权、目标身份、`createWritable`/`write`/`close` 均不在本协议；下载请求也不能证明用户已保存。调用成功后的文件仍可能被后续写入覆盖，事件没有不可变字节快照，也没有绑定世代，绝不可直接交给现有 watcher 视为安全写回信号。
2. 取消选择器不写虚拟文件，但选择器本身可能已有浏览器侧副作用；失败也可能留下部分虚拟数据。GUI 现有分支并不都检查返回值，协议不得为了观察偷偷改变 New/Exit 或 GUI 业务逻辑。Exit 可立即终止，终态可能来不及轮询。
3. `WriteXMLFile` 的 bool、libxml 关闭失败传播及异常安全尚待验证；实际发生异步/其他线程对同路径写入时，事件先后不能保证快照一致。若不能证明关闭和序列化边界，不能宣称完整可写回的 XML。
4. 有界资源必然可能丢记录，后台冻结、异常、重启和旧前端都会造成盲区；`lossEpoch` 只能在后续成功通信时报告。虚拟路径可能包含敏感信息，日志和诊断 UI 应最小化、避免持久化或遥测，访问范围与生命周期须另行审查。
5. 不能据此实现 Save As 句柄匹配、解决同名路径重绑竞争、覆盖 API 写、推断 GUI 所有导出、绕过权限或证明同磁盘目标不同。协议是实验观察规格，不是现有功能或测试结果。

## 7. 分步测试计划（未来实施；本文未运行）

1. **纯模型与编码**：注入极小条数/字节配额，检查 FIFO、唯一 seq/opId、JSON 特殊字符及 UTF-8 字节计量、极长路径单条拒绝、边界恰满与超一、保留先入事件、lossEpoch/sticky、耗尽不回绕；模拟内存分配失败，不影响写调用。
2. **并发与传输**：生产与 take 交错，断言事件和 epoch 同锁线性化，无重复/越界；模拟 take 后 JSON 构造或页面解析失败、首末事件丢失、停轮询、重连、session 改变，所有未决归 unknown，绝不恢复成成功。确认其他镜像输出和 modal 对话框不被观察通道饥饿。
3. **逐 GUI 分支注入**：Save 已命名与未命名、Save As、Save Set、New→Save、Exit→Save，分别模拟选择器/选择集取消、成功、false、异常和中途退出；对比调用次数、原有返回/退出行为和事件的操作身份、实际路径、set。其他菜单、API `WriteVSPFile` 不应产生 GUI 事件；未覆盖路径明确列出。
4. **虚拟 FS 故障**：在隔离测试环境注入序列化、打开、写、关闭失败及部分文件，校验 failed/unknown 不称取消或成功；验证 libxml 对关闭错误的实际传播，比较成功后 XML 可读性与源模型，但不把这当并发快照证明。
5. **协议兼容矩阵**：旧页/新引擎、新页/旧引擎、新页/新引擎、未协商、拒绝版本、重复请求、超时与丢包；默认关闭时字节级确认旧消息合同与行为不变，检查无能力应答不阻塞 GUI。
6. **与写回隔离**：模拟同名重绑、相同 mtime/size 不同内容、同一 handle 多路径、权限拒绝、close 悬挂、选择器取消与扩展名变化；断言事件不会触发磁盘写、下载或把 watcher 旧结果标为新绑定已保存，仍遵循文件写回设计的失败语义。
7. **浏览器手工实验**：仅在明确隔离的实验构建、临时模型和文件中，分别在 Chromium 及无 File System Access 的浏览器检查前台/后台、取消、页面关闭、Exit、快速连续保存和过载。记录引擎版本、操作、事件、lossEpoch、虚拟 FS 与磁盘分别的观测；测试前禁用或隔离现有自动写回，避免把真实磁盘结果误归于本协议。真实用户激活及浏览器限制不可由 mock 替代。

通过上述阶段只证明观察实现与其测试范围一致；生产启用或任何自动写回需独立设计审查、完整快照证明、兼容性验证和用户明确批准。
