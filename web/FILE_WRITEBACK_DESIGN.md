# 浏览器文件写回：身份、重绑及悬挂操作协议（设计稿，未实现）

## 范围与现状

仅讨论当前浏览器页中的已打开/另存文件写回及其与结果保存的边接口；不声称实现或测试通过。现有 `web/frontend/src/api/wasmEngine.ts` 的 `linked` 以 HOME 下文件名路径为键，`link` 替换记录；`watchLinked` 以 mtime/size 和一次不变轮询判稳，再由 `deliver` 异步申请权限和写入。旧记录上的 `writing` 与新记录隔离。打开时先把选择的数据写到同名 HOME 路径再 link；另存则先 link 后回复引擎。`askToWrite` 在异步选取、读取之后运行，并不能保证仍有用户激活；定时写回亦不能假设有激活。`solverResults` 从 linked 读取模型句柄，应保留其合同。现有判稳本身也不能证明写入已经结束、同 mtime/size 的内容变化可能漏检，本方案不把它误称为可靠保存完成信号。

## 合同与身份

1. 路径仅标识 WASM 内部位置，不代表磁盘身份；文件名、句柄对象引用、mtime/size 均不能证明物理文件相同。每次 link/rebind 创建不可复用的绑定世代（bindingId），绑定含虚拟路径、句柄或下载模式、显示名、状态及版本。每次快照不可变，携带 bindingId、序号和字节；过期快照不得借用新绑定的句柄。
2. 目标身份使用 `isSameEntry`，建立仅在本页生命周期有效的目标记录；不同句柄仅在比较结果为 true 时合并。false 才能判为不同；方法缺失、抛出、reject、超时、不结束都属于 unknown，不得降级为不同，也不得以同名或对象引用之外的猜测合并。对象完全相同可直接认同；比较还要防护同步抛错。不同目标可独立执行，不能持有跨全部目标的异步全局锁。
3. 目标识别采用登记-比较-确认：同步登记候选和递增顺序号，再异步比较所有此前尚可能写入的目标与候选（包括在途、失效但尚未结算者）；后登记者对先登记者负责消除歧义，先登记者不等待后者。candidate 未完成与所有相关对象的比较时不得写磁盘；相同则加入已有目标串行通道；有 unknown 则 candidate 进入身份未确认状态，可取消/提示，但不阻塞先登记目标或无关已确认目标。完成比较后在无 await 的同步临界段复核集合版本，补比较新出现的、按顺序必须比较的对象；不得因竞争遗漏。若存量发现多个通道其实相同，冻结相关目标、等待在途结算后合并；存量未知冲突不得继续按互不相关写入。每次切换身份只在同步步骤发布，不在持锁期间等待浏览器 API。
4. 每个已确认目标至多一个未结算的写操作；写同一目标的后续操作按版本序列排队，允许合并尚未开始且同一有效绑定的中间快照，不能跨绑定悄悄覆盖用户保存意图。新绑定即使拥有另一条虚拟路径，只要是同一目标，也共享此通道。保留明确的 pending/failed 状态，不把排队当作保存成功。

## 重绑、旧写与虚拟文件导入

- 在任何覆盖同名 WASM 文件之前同步使旧 path 绑定失效并暂停该 path 的 watcher；导入在隔离的 staging 路径先读完整内容，确认提交时再覆盖并为新绑定设置当前 stat 基线，最后恢复 watcher。失败、取消时不破坏旧绑定和旧文件，且不得把导入的数据作为旧绑定的保存；必要时备份并恢复内部文件，逐项处理 FS 失败。已有进行中的 WASM 写与引擎同步点也须明确；仅在单线程 JS 同步操作不能证明与 pthread 的 FS 写互斥，未建立引擎级序列化之前只能缩小窗口，不能承诺原子性。
- 世代失效时丢弃未开始的旧快照并通知用户（或事先询问保存/取消）；正在 await 的旧任务每次恢复后检查世代与目标，尚未 close 时尝试 `abort()`，不自动向新目标重新投递；失败必须可见。已有 `close()` 发出后无法可靠撤销或保证回滚，必须让相同目标通道继续占用直至其实际 settle；新绑定能建立但不得绕过该通道写同一目标。close 成功后只能报告旧版本最终完成，不能将其标为新版本已保存。新/旧路径碰撞按目标串行，重绑不同目标则允许彼此独立，但旧任务仍有明确可见状态。
- Save As 先识别并注册目标、设定绑定和基线，再答复引擎；打开也使用同一身份流程。不能在文件对话框里无限等待身份比较：设可取消/超时的 UI 等待，超时回复引擎取消，保留已知上下文并禁止这次写入，不释放尚未 settle 的危险资源。确保每个 dialog seq 恰好回答一次，所有异常有明确失败结果。异步文件操作超时只是 UI 超时，不代表底层操作已停止。

## 用户激活、授权与下载

- 由用户明确点击文件选择/授权按钮的同步事件处理器直接调用 `showOpenFilePicker`、`showSaveFilePicker` 或 `requestPermission`，调用前不 await（包括 query、身份比较、排队）；调用后的 Promise 可以异步处理。来自引擎轮询的 file dialog 不是可信用户手势；应呈现可取消的 UI，由真实点击直接调用 picker，再回复引擎，避免依赖跨线程及异步轮询的瞬态激活。无法在这条路径保持引擎对话框的可交互性时，先验证镜像对话框泵与 UI 的行为，不能承诺有效。
- 后台写回只 query 已有权限，不在定时任务中 requestPermission。权限为 prompt/denied/unknown 或 query 缺失、拒绝、异常时停在“需授权/无法确认”，保留待写版本并显示明确按钮；按钮直接 requestPermission，返回 granted 后仍需检查世代及目标通道，才写。不要假设 picker 返回、await getFile 或一次权限请求后用户激活依然存在；选择器返回的已有 grant 可查询使用。拒绝、关闭、API 不支持和安全策略错误分别反馈；取消不视为成功。
- 下载模式须明确标记为“生成下载/已请求下载”，浏览器能否完成保存不可观测，不能称已写回原文件。对权限拒绝或写入失败不能静默降级下载冒充原位保存；提供由用户点击的下载备份、重试授权、另存选项，提供的备份是失败时保留的不可变字节快照。

## 有界协调与失败语义

- 同一目标在途 createWritable/write/close 永不 settle 时该目标冻结，未知身份的候选只冻结自身；绝不因超时放行同一目标，因为操作可能迟到并覆盖新内容。watcher 继续运行但该目标仅保留最新未开始快照和必要失败信息，限制待处理目标、候选和保留字节大小；到限后停止接收新快照并明确报错，绝不静默丢弃唯一备份。资源管理须同时限制原生调用数，禁用对同一悬挂操作的无界重复重试。abort 最多尝试一次且它本身也可能悬挂；只有原写入及必要清理确定结束后才解除隔离。
- `isSameEntry` 卡住时可以停止等待和显示恢复按钮，但不能宣称文件不同；用户选择另存也需经过同样身份检查。受影响候选不持全局锁，不阻塞正常已确认目标；如所有候选都未知，新增写入可能不可用，这是避免覆盖的必要代价。页面关闭/重载也不能证明未结算的浏览器提交已取消，提示用户核对磁盘文件，不能以重载作为安全解锁保证。
- 捕获 read/stat、query、createWritable、write、close、abort、isSameEntry、picker 和下载触发全部异常。针对每次用户操作报告：取消、未授权、身份未知、队列中、写入中、失败、已提交（仅 close 成功）或已请求下载；绝不 fire-and-forget 未处理 rejection。写失败保留快照；写失败后磁盘状态可能未知，必须显式警示并在同目标队列已安全结算后才允许重试。不要将失败状态重置为已保存。回收确定已无待写/在途/引用的历史目标，冻结目标由配额约束，不能承诺浏览器永久悬挂时零资源占用。

## 推荐可小步交付

1. 先加入纯状态机/注入依赖的单元测试，覆盖世代失效、竞态及明确失败；现有行为不变，不宣称修复。
2. 显示失败和显式用户激活路径：文件对话框经用户点击 picker；后台无权限仅暂停与通知，下载明确为备份。验证浏览器的激活与取消行为。
3. 将旧绑定作废、路径导入隔离、不可变快照引入，并确保迟到回调不能将新绑定标为成功；明确 close 已发出不可撤销。
4. 建立目标身份比较及每目标通道，unknown fail-closed；加容量限制和取消 UI，避免全局 async 锁。迁移现有链接与 solverResults 消费方式，保持模型句柄关联。
5. 完整写回的必要条件：引擎在序列化成功并关闭 WASM 文件后，发出包含路径、写入世代的完成事件；在该线程一致性边界获取不可变字节快照，或以其他已证明方式保证快照与事件世代一致。失败、取消、部分写入不发成功事件；解决与 GUI 普通 Save、Save As、其他写路径的覆盖关系，并对同一路径重叠写入建立顺序。若没有这个边界，mtime/size 不变一个轮询周期仍可能是序列化中途，不能据此自动投递并宣称安全；保守方案是暂停自动写回并提示无法确认完整性，而非只做静默周期调参。

## 必测边界

不同路径同文件、同路径不同文件、不同句柄同文件、同名不同文件；相继/同时绑定及比较顺序交错；isSameEntry true/false、同步抛、异步 reject、缺失、永不完成；旧任务在 query、createWritable、write、close 每一 await 点重绑；close 卡住及迟到成功；导入同名文件与 watcher 交错；新旧内容 mtime/size 相同；同一目标连续保存并发及不同目标独立；取消选择、权限 prompt/denied/granted/异常、无用户激活、用户点击授权；浏览器不支持 picker；失败后重试、容量到限、对话框恰好一次答复；结果保存关联正确。手工覆盖 Chromium 和无 File System Access 的浏览器；测试不能把 mock 的瞬态激活等同真实浏览器。
